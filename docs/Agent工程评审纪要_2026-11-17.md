## 一、事故链复盘(纹章士推荐)

1. **切片事故**:消费端 agent 以默认 `top_n=3` 调用 emblem_fit,42 分并列的 7 家纹章士按 `(−分, id)` 排序只返回字母序前 3,并列段内未做权衡即当作推荐输出。
2. **记忆冒充事实**:agent 凭训练记忆断言数据层条目"不在游戏中",违反"数字与事实只准引用工具返回值"的项目规则(该断言本身是错的,数据是对的)。
3. **类型错配(隐性)**:语义层不区分技能类型,Engage Attack(如 Lodestar Rush)被计入"同步技协同"组件,字段名与口径不一致。

- 事实字段接入:engage 技要点 / engage 武器数值 / 入手章节(DLC、剧透)。

## 三、架构原则(讨论结论)

1. **约束的实现位置决定可靠性**,通道可靠性排序:输入 schema/默认值 > 输出内嵌事实 > 工具 description > server instructions > 消费端自身纪律。必须处处成立的规则只住前两层。
2. **expand-then-filter**:检索要宽,过滤是模型的事;服务端切片与"反锚定、事实综合"架构原则冲突。
3. **渐进披露**:索引层先走、详情按需(瘦身参数/Resources),防归因错配与上下文膨胀,而非退回服务端切片。
4. **封存封闭集,组合开放集**:compound tool 只封"高频×组装唯一×可枚举"的路径(paved road),复杂请求 = playbook 教编排 + 原子工具正交组合。
5. **数据源不许质疑**(项目硬规则);**社区考卷只用于训练/校准引擎,不进运行时判断**(项目硬规则)。
6. MCP 是能力交付协议而非行为约束协议:对"接入任意 LLM"零假设,凡依赖"消费端守纪律"的设计都是缺陷。

## 四、评价谓词("强度/适合")的操作化——行业方案

问题学名:**未定义谓词**。LLM 遇到无操作化定义的评价词时回退训练先验,导致跨模型/跨会话不一致(本项目三次分歧:安娜、花月、罗伊,实为三种隐含定义打架)。行业五模式:

| 模式 | 做法 | 代表 | 本项目落点 |
|---|---|---|---|
| 1. Rubric 卡 | 评价词展开为判据清单+锚点+判分格式 | MT-Bench、G-Eval、Prometheus、Langfuse | server 发"强度"三口径 rubric 卡(面板型/期望型/技能定义型,各配锚点角色) |
| 2. 指标即代码/语义层 | 指标=定义+公式+校准依据,定义一次处处引用 | dbt MetricFlow、Cube、LookML | "强度"指标卡:`calibrate_tier` 校准结果升格为 MCP resource(`engage://glossary/tier`),消费端只准引用 |
| 3. 拆解可测谓词 | 模糊目标拆成明确可测子标准,能用确定性检查的不用 LLM | Anthropic success criteria、OpenAI eval best practices、promptfoo `llm-rubric` | "适合"拆为:资格/组件分/补正收益/机动/队伍空位 |
| 4. 效用函数显式化 | 效用不可推断只能引出;推荐前结构化追问 | 推荐系统实践、agent 澄清模式 | playbook 硬规则:推荐类问题先问玩法取向,效用未定不下"更适合"结论 |
| 5. 一致性成为考卷 | 同问跨模型/跨会话一致性作为版本化 eval | DeepEval/promptfoo 版本化 metric | 已裁决结论固化为一致性场景(CI 资产) |

收敛方向:**评价词要么操作化为代码中的指标,要么显式移交给人(效用追问),不能留在模型自由裁量里**。"事实裸奔+模型综合"对强模型够用,对任意 LLM 不稳定。
